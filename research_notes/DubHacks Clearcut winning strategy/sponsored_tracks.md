## What SpaceXAI, xAI, and Cursor actually require

### Takeaway
On the DubHacks page, eligibility is two clauses: the project must be built with Cursor, and it must use the Grok Imagine API or the Grok Voice API. Imagine and Voice are alternatives, not a pair. Grok Bot is bonus points only. Nothing on that page asks for generated images, a Cursor transcript, or a specific proof file. xAI’s current Voice API is a realtime WebSocket at `wss://api.x.ai/v1/realtime` with model `grok-voice-latest` (alias of `grok-voice-3.0`). The DubHacks prompt also says “Real space data goes in,” but that sentence is not inside the “To be eligible” paragraph.

### Cited Findings
- Eligibility sentence: “To be eligible, your project must be built with Cursor. The more you use Cursor, the more likely you are to win. You must also use the Grok Imagine or Voice API in your project. Bonus points if you use Grok Bot for project planning and team collaboration.” — [Sponsored Side Tracks](https://dubhacks.notion.site/26-Sponsored-Side-Tracks-5e3ff32c1d7e834d9844812256c9fa06)
- The same OR appears on BigRed//Hacks with nearly the same words, including “Bonus points, if you use Grok Bot.” That page also does not define a Cursor proof artifact. — [BigRed//Hacks 2026 Devpost](https://bigredhacks2026.devpost.com/)
- A different event, DivHacks, used stricter marketing copy: “You’ll code with Cursor, generate images or videos with Grok Imagine, and integrate voice with Grok Voice.” That is an “and,” and it is not the DubHacks page. DivHacks also promised Cursor and Grok credits to participants. DubHacks’ Notion text does not mention credits. — [DivHacks SpaceXAI challenge](https://www.mlh.com/events/divhacks-14/challenges/01a0e99d-0eeb-7082-835a-a79167600ea1)
- xAI Voice overview lists three products: Speech to Speech (`grok-voice-latest`, realtime, $0.08/min, endpoint `/v1/realtime`), Text to Speech ($15.00 per 1M characters, `/v1/tts`), Speech to Text (batch $0.10/hour, streaming $0.20/hour, `/v1/stt`). — [xAI Voice overview](https://docs.x.ai/developers/model-capabilities/audio/voice)
- Speech-to-speech quickstart connects to `wss://api.x.ai/v1/realtime?model=grok-voice-latest` with `Authorization: Bearer $XAI_API_KEY`, then `session.update` (`voice`, `instructions`, `turn_detection`) and `response.create`. Browser clients are told to use an ephemeral client secret because browsers cannot set the Authorization header. `grok-voice-latest` is an alias for `grok-voice-3.0`. `grok-voice-2.0` is deprecated. The docs say the 3.0 API matches 2.0 at the same price. — [xAI Speech to Speech](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech)
- Server-side auth is the API key. Client-side auth is an ephemeral token from `POST /v1/realtime/client_secrets`, passed as a Bearer token or as `xai-client-secret.<token>`. — [xAI Voice REST reference](https://docs.x.ai/developers/rest-api-reference/inference/voice)
- A published browser example is a React client with a Python or Node backend. — [xAI web voice assistant cookbook](https://docs.x.ai/cookbook/examples/voice-agent-web)
- Cursor intensity is a judging factor (“The more you use Cursor, the more likely you are to win”), not a separate API. No DubHacks sentence requires a screenshot, a `.cursor` rules file, or agent logs. — [Sponsored Side Tracks](https://dubhacks.notion.site/26-Sponsored-Side-Tracks-5e3ff32c1d7e834d9844812256c9fa06)

### Inferences
- Grok Voice for an “Ask Clearcut” Q&A meets the written API clause without Grok Imagine. A text-only chat completion would not, because the clause names “the Grok Imagine or Voice API.” TTS (`/v1/tts`) and the realtime voice socket are both under the Voice API overview; the track page does not say which Voice endpoint counts. A realtime or TTS call is the safer reading of “Voice API” than speech-to-text alone.
- Satellite or aerial imagery is not the same phrase as “real space data.” The eligibility paragraph does not say “must ingest space data.” Judges can still score the project down against the prompt. That risk is a fit issue, not a missing API.
- Building the repo in Cursor satisfies the only Cursor sentence that uses “must.” There is no published artifact to fake, and none that was found to submit.

### Gaps
- Grok Imagine’s endpoint, model id, and whether DubHacks supplies an xAI key were not verified. Imagine was not required once Voice is used, so the Imagine docs were not fetched.
- No DubHacks page links a Grok Bot doc. What “Grok Bot” means (Telegram, Slack, Cursor, or an xAI product) and how bonus points are scored was not verified.
- No page states how judges will check that Cursor was used.
- Whether Voice API credits are provided at DubHacks, as DivHacks promised for its own event, was not verified.

## VEYZL eligibility and whether the audit fits overnight

### Takeaway
Eligibility on the DubHacks page is a working AI project, a GitHub-connected VEYZL check whose result is visible on a pull request, and evidence that findings changed what shipped. A passing screenshot is explicitly not enough. The public quickstart is five steps on a free account and can be started the same night the repo exists. Whether a first audit returns a real, fixable finding before Sunday morning, and whether it can call a Perceptron endpoint, was not verified.

### Cited Findings
- DubHacks eligibility bullets: working AI project; “A real VEYZL audit on the repo (GitHub connected, check run, result visible on a pull request)”; “Evidence the findings changed the build, not just a screenshot of a passing check”; short demo of issue, fix, and why it matters. “VEYZL access is free for participating teams during the event.” — [Sponsored Side Tracks](https://dubhacks.notion.site/26-Sponsored-Side-Tracks-5e3ff32c1d7e834d9844812256c9fa06)
- Product steps: (1) install the VEYZL GitHub App and create a project, (2) review the detected system profile and triggered controls, (3) open a pull request so VEYZL runs dataset, API, or hybrid audits and posts a `VEYZL Audit` status check, (4) optional branch protection so a failing check stops the merge, (5) export signed evidence. Controls cited include EU AI Act, NIST AI RMF, ISO/IEC 42001, ECOA, and the Fair Housing Act. Unverifiable results are “inconclusive instead of passing silently.” — [VEYZL](https://veyzl.ai/)
- Developer quickstart matches those steps and says the Free plan “is the safe place to try VEYZL”: audits on every push and pull request, findings on the PR, merges never blocked. Re-run without a new commit via “Run audit” on the project page. There is no separate sandbox. — [VEYZL developer portal](https://veyzl.ai/developers)
- Public plans: Free is $0, 1 AI system, unlimited runs, findings and fix guidance, 30 days of evidence, “Advisory only: merges are not blocked.” Startup is $5/month, up to 3 AI systems, blocking checks, signed exports, 1-year retention. — [VEYZL](https://veyzl.ai/)
- The live-audit SDK (`@veyzl/sdk`) wraps OpenAI, Anthropic, and Google GenAI Node clients only. It records prompts and responses and does not block the call. Live audits must be enabled or ingest returns 403. — [VEYZL developer portal](https://veyzl.ai/developers)
- The track examples are a support/refund agent, a study or health assistant, or “Any agent or model app where the team uses the audit to fix a real issue, then shows the before and after.” — [Sponsored Side Tracks](https://dubhacks.notion.site/26-Sponsored-Side-Tracks-5e3ff32c1d7e834d9844812256c9fa06)
- Security page says standard flows do not store raw dataset rows, model weights, or individual predictions; evidence is hashes, metrics, and configuration. It also says “Exact fields depend on your integration.” Last updated 5 Sep 2026. SOC 2 Type II is “in progress,” not claimed as done. — [VEYZL security](https://veyzl.ai/security)

### Inferences
- The DubHacks win condition does not require a blocking merge. Free-tier advisory checks can satisfy “check run, result visible on a pull request” if the team then changes code and shows the second run. Paying $5 for Startup is only needed if they want the merge actually blocked or a signed export.
- Overnight is plausible for install, profile review, one PR, and a code change, because the published path has no workshop, no hardware, and a manual re-run button. It is not plausible to promise a specific EU AI Act finding in advance. A green check with no product change fails the track’s own words.
- Perceptron is not one of the three wrapped live-audit clients. A Python `perceptron` app can still be audited if VEYZL’s repo profiler detects the AI surface. That detection behavior is not documented on the pages fetched. If the audit instead needs a public HTTP endpoint, exposing one becomes extra work before the check can “run targeted tests against the live model.”

### Gaps
- No published duration for a first audit (minutes versus hours) and no hackathon-specific onboarding beyond “access is free.”
- The How it works page returned no body, so model-configuration and gating details are unverified. — [VEYZL how it works](https://veyzl.ai/how-it-works)
- Whether DubHacks “lifetime pro” upgrades teams off the advisory Free plan was not verified.
- No source confirms that a Perceptron Python client is detected or that satellite images would be sent to VEYZL. The security page says raw rows and individual predictions are not stored in standard flows, which is relevant to an evidence tool but is not a hackathon rule.

## Poor fits, time traps, and the three slots

### Takeaway

Perceptron robotics, Photon, and T-Mobile are poor fits. Cloudforce cannot be scored until its HTML brief is opened. VEYZL is the honest governance slot if the first audit returns a real finding; SideShift is the lower-risk slot because it requires no sponsor API.
